# jukebox-ui — keep the Volumio touch UI fast

The DSI touch UI on this jukebox felt sluggish and scrolling was not fluid.
This kit fixes the causes we measured on the live box and keeps them fixed.

## What was wrong

| # | Cause | Evidence |
|---|-------|----------|
| 1 | Chromium launched with `--disable-gpu-compositing --disable-3d-apis`, forcing **software compositing** | scroll CPU 55% of one core |
| 2 | Debian/RPi `/etc/chromium.d/00-rpi-vars` adds `--force-renderer-accessibility` | work per frame |
| 3 | The active UI (`now_playing` web client) applies a full-screen **50px** background blur plus **20–30px** screen filters | scroll CPU 40% of one core |
| 4 | Volumio forces **HDMI-1 on** (`hdmi_force_hotplug=1` in `volumioconfig.txt`), so the X screen is 848×480 while the physical DSI panel is 800×480 → right ~48px clipped and the touch mapping ~6% off | `xrandr` before/after |

Measured scroll cost (synthetic XTest scroll on the Queue screen, browser+GPU+Xorg CPU):

```
before everything ........ 55 %
after (1) ................ 22 %
after (1)(2) ............. 38–40 %   (scroll now on a fuller screen)
after (1)(2)(3) .......... 11 %
```

(The GPU is genuinely used now — V3D IRQ count climbs during scroll.)

## What this does

`jukebox-ui.sh apply` (idempotent):

1. Removes `--disable-gpu-compositing` / `--disable-3d-apis` from `/opt/volumiokiosk.sh`.
2. Removes `--force-renderer-accessibility` from `/etc/chromium.d/00-rpi-vars`.
3. Lightens the CSS blur constants in the `now_playing` client build.
4. Inserts `xrandr --output HDMI-1 --off` into the kiosk script right after
   `openbox-session &`, so the X screen is the native 800×480 DSI panel.

`jukebox-ui-guard.path` watches `/opt/volumiokiosk.sh` and
`/etc/chromium.d/00-rpi-vars` and re-applies whenever Volumio or the Touch
Display plugin rewrites them (saving a setting on the plugin page regenerates
the kiosk script).

## Install

```sh
# from the host, as root:
sudo bash install.sh

# or from a dev machine (adjust the host/user to your setup):
scp install.sh jukebox-ui.sh jukebox-ui-guard.service jukebox-ui-guard.path \
    volumio@<host>:/tmp/
ssh volumio@<host> 'cd /tmp && sudo bash install.sh'
```

`<host>` is whatever mDNS name or IP your Volumio box has. `sudo` needs the
`volumio` user's password (ask for it; nothing is stored in this repo).

Then reboot once so the kiosk starts from a clean state:

```sh
ssh volumio@<host> 'sudo reboot'
```

## Status / verify

```sh
sudo /usr/local/jukebox-ui/jukebox-ui.sh status
sudo /usr/local/jukebox-ui/jukebox-ui.sh verify
```

## Notes / caveats

- **Do not enable HDMI audio.** HDMI here is only a phantom connector that
  Volumio forces on; this kit turns the output off. Audio stays on the I2S DAC
  and the USB second output (`software/volumio-dual-output/`). See the
  `jukebox` skill's golden rules.
- The `now_playing` CSS is patched in the installed plugin build. A future
  plugin update replaces it; re-run `apply` (the guard only watches the two
  files above, so run it manually after updating the plugin).
- `hdmi_force_hotplug=1` in `/boot/volumioconfig.txt` is left untouched (it is
  regenerated by Volumio); the HDMI output is turned off inside the X session
  instead, which is what actually fixes the clipping.
- Health: the boot log shows `EXT4-fs (mmcblk0p2): warning: mounting fs with
  errors` — worth an `e2fsck` at some point; unrelated to UI speed.

## After an update — what to do

An update can undo these fixes. The **guard only covers some of it**, so after
any update run `apply` and `verify`.

| What updated | What it breaks | Action |
|---|---|---|
| **Touch Display plugin** (or saving any setting on its page) | regenerates `/opt/volumiokiosk.sh`, bringing back `--disable-gpu-compositing` / `--disable-3d-apis` and dropping the HDMI-off line | guard auto-fixes within seconds; confirm with `verify` |
| **`now_playing` plugin** | replaces its installed CSS → heavy blurs come back (the guard does **not** watch this) | **run `apply` manually** |
| **Volumio OS / `chromium` package** | may restart the kiosk and re-add `--force-renderer-accessibility` in `/etc/chromium.d/00-rpi-vars`; Volumio may rewrite boot files | run `apply`; if the screen is 848px again, reboot |
| **Kernel / `/boot`** | `cmdline.txt` / `volumioconfig.txt` rewritten; `hdmi_force_hotplug` comes back | `apply` (HDMI-off is inside the X session, so no boot edit needed) |

Recommended, right after any update:

```sh
sudo /usr/local/jukebox-ui/jukebox-ui.sh apply
sudo /usr/local/jukebox-ui/jukebox-ui.sh verify     # expect all "ok"
```

Then check the `now_playing` CSS really took (it is not guarded):

```sh
grep -o -- '--default-background-blur:[0-9]*px' \
  /data/plugins/user_interface/now_playing/dist/app/client/build/static/css/main.*.css
# expect: :10px   (if you see :50px, run apply again)
```

If the X screen is not `800x480` after `apply`, reboot once so the kiosk
starts clean. If you reinstall the plugin from scratch, `install.sh` sets
everything up again; re-running it is safe (idempotent).
